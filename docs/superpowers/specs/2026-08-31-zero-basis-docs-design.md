## 一、背景与问题诊断

现 README（657 行，中英双语单文件）08-30 已做过「过期与不准」修复，但首读可懂性的结构性问题未动。四个根因：

1. **第一句就假设读者懂 DSH**：DSH 是什么、给谁用的全文无一句白话注释；「挂载」「provider」「预设」「dock」直接使用——违反顶级规则《面向人的文档写法规范》（默认零基础、术语说人话）。
2. **「对他有什么帮助」没有正面回答**：具体收益（贴图自动走视觉模型/写码走编码模型/闲聊翻译走便宜模型/每步决策可见）埋在 12 条带版本号的特性 bullet 里；无「适合谁/不适合谁」。
3. **全文不分层，维护者语言占访客动线**：路线图+版本史约占 1/4（commit hash、验收清单编号、测试数）；配置表与 `.pre-v3/v4/v5` 迁移史是装机后才需要的内容，全部平铺。
4. **缺三秒电梯陈述**：读三段才能拼出「是什么」，做不到 3 秒回答「这是什么 + 我能得到什么 + 适不适合我」。

## 二、目标与非目标

**目标**：陌生访客 3 秒知道项目是什么、10 秒知道对自己有什么用、1 分钟知道适不适合自己、5 分钟能装上跑通；深度内容有清晰落点；版本史单一事实源 + CI 守护。

**非目标**：不改任何代码与路由语义；不做 positioning 竞争地图 v2（0.8.5-T5）；不动 hero 图与视觉资产；不动 superpowers specs/plans 历史档案；不建文档站。

## 五、白话化与事实纪律

- **白话原则**：一切术语第一次出现必须白话注释（DSH、挂载、provider、预设、多模态、token、effort 等）；每句一个意思；先场景后功能。对照《面向人的文档写法规范》发出前自查清单。
- **新增事实断言白名单**：本轮唯一新增事实断言 = DSH 的一句话介绍。落稿前对照 DSH 官方描述（npm `@deepseek-ai/dsh` / 官方 README）核实措辞，spec 不预设表述。
- **事实零漂移**：现有数字与事实（v1.0.0、497/497+31 文件、DSH 版本窗、模型表、配置键默认值）不得在改写中变化；实施时逐条对照源文档与源码（沿 08-30 事实核查做法）。
- **证据链不断**：路线图证据表整体迁移，不删改；发布门禁措辞同步。
