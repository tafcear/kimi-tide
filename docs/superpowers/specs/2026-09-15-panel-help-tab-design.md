## 1. 背景与现状

**起因的机制实证**（本会话已核）：`reviewTriggerHit`（`rules.ts:186-204`）首句即 `if (flow.trigger !== 'keywords' || !flow.keywordGroup) continue` ⇒ `trigger: manual` 的评审流**永不武装**，与 reviewer 选哪个模型无关。`claimedReviewGroups`（`rules.ts:169-178`）同样只认 `trigger === 'keywords'`。⇒ 用户的困惑不是操作失误，是**界面没有解释字段分工**：`reviewer`（谁来评）与 `trigger`（何时评）是两个字段，界面上并排两个下拉，没有一个字说明区别。

**现有解释面盘点**（实读统计）：

| 位置 | 已有 | 缺口 |
|---|---|---|
| `TideDock.tsx` | **11 处** `title=`（多为复述标签：「周配额已用比例」） | 元素**是什么**、数字**从哪来**、**为什么置灰** |
| `ReasonPanel.tsx` | 配置来源 + 决策理由 + 最近流事件 | **0 处** tooltip；术语（打底/认领/判否/特异度）无解释 |
| `SettingsCard.tsx` | **6 处** `title=` + 少量提示常量（`FALLBACK_HINTS`，:114-115） | 字段语义、字段间分工、当前值意味着什么 |
| 仓库文档 | `README` 双语、`docs/router.md`（598 行，语义极全） | **不在界面里**——用户看设置页时读不到 |

**页签现状**（本设计要动的代码）：`SettingsCard.tsx:455` `useState<'route'|'flows'|'trial'>`；:720-733 `role="tablist"` + 三个 `role="tab"` 按钮；面板切换靠 **CSS 可见性**（`styles.ts:163-164`，区块保持挂载）。**已知 a11y 债**：缺 `tabpanel` / `aria-controls` / 方向键（UI 评审 C11/N5，`_ui-review-2026-08-29.md:43`）——加第四个页签时顺手还清（§6）。

**可用的实时数据**：`SettingsCard` 持有 `snapshot = useSyncExternalStore(store.subscribe, store.getSnapshot, store.getSnapshot)`（预设/规则/关键词组/flows/activePreset 全在其中）⇒ 说明页可以渲染**当前值**，不必另开数据通道。

## 2. 目标与非目标

**目标**：

1. **一处集中、可扫读**：设置页第四个页签「说明」，按界面位置分区组织，`README`/`router.md` 仍是深水区，说明页是**界面内的那层**。
2. **状态感知（本设计的核心差异点）**：关键条目**带当前值与其后果**——「触发方式：当前 `手动` ⇒ 关键词命中不会触发评审（改为「关键词组」并选组后才按轮末评审）」。静态术语表救不了「为什么没触发」这类问题（§1 已证）。
3. **覆盖完整**：dock 每个可视元素 + 设置页全部语义 + 术语小表 + 命令清单 + **常见疑问（症状→原因）**。
4. **与已发布行为同版一致**：说明内容只描述**本版实际 ship 的行为**，并把「新增特性必须同提交补说明条目」写成发布检查项 + 测试兜底（防文档腐烂）。
5. **顺手还 a11y 债**：四页签具备完整 tab/tabpanel 语义与键盘操作（C11/N5）。

**非目标**：

- 首次使用引导/onboarding 遮罩、交互式教程（另一件事，先不做）；
- 说明页内搜索框（八个分区扫读即可，YAGNI）；
- 就地「?」内联提示（用户已裁定形态 A；既有就地 tooltip 保留不动）；
- 多语言（先中文，与卡片其余文案一致；内容结构留 en 位，见 §10）；
- 解释 DSH 宿主自身功能（只管月汐自己的东西）。

## 3. 信息架构（八个分区）

分区用现有折叠样式（`<details>/<summary>`，与「关键词组」折叠区同款，`SettingsCard.tsx:1087-1089` 先例）。**默认只展开 ①**，其余折叠——避免一屏压倒用户。单条 ≤3 行，超出者拆进 ⑥ 术语表。

### ① 面板速览（dock 每个元素）

表格三列：**元素 / 它是什么 / 什么时候变灰或消失**。逐元素（对应 `TideDock.tsx` 实际渲染项）：

| 元素 | 说明要点 |
|---|---|
| 月汐标签 | 插件身份；hover 提示「路由设置见 设置 → 月汐」 |
| 预设 chip | 当前激活预设名（`关闭` = 路由关闭时显式关闭，非故障） |
| 打底 chip | 未命中任何规则时用的默认模型 |
| 决策目标 chip | **本步实际路由到的目标**（与打底不同才说明规则/显式 @ 生效了） |
| 决策开关（▸/▾） | 展开决策可观测悬浮层；**打底与 keep 不上 chip**——「看不到原因条」不是故障 |
| 周配额槽 / 5h 槽 | 当前命中目标 provider 的用量窗；`—` = 目标无配额源或取数失败 |
| 余额槽（若同版发用量/余额特性） | API 计费源的余额；`—` 同上 |
| 图像三态（原/述/盲） | 本会话图片：原生视觉 / 已转述 / 盲答（盲 > 0 = 有图但文本模型看不到）；**无图会话不渲染此行** |
| 取数时间 + 刷新 | 上次成功取数时刻；`(过期)` = 最近一次刷新失败 |
| 总览入口（同上，若发） | 一屏看全部源的用量/余额 |
| Kimi 未接入警示 | 缺路由或 key 时的配置指引，非错误告警 |

### ② 路由语义

预设与激活、规则链**首条命中生效**、**特异度排序**（命中词数多者优先、平手按列表序、带图恒第一）、打底（未命中 ≠ 不动）、目标不可用则**跳过该规则降级**、显式 `@` 最优先、带图三态（锁存/盲答/懒转述）及各自后果。

### ③ 关键词与匹配语义

纯 ASCII 词按**词边界**（`decode` 不误中 `code`）、中文/混合/短语按**子串**、大小写不敏感、**最少命中词数**（`minHits`）怎么算、词表可改可自建。

### ④ 协作流语义（**本页最重要的一节**，直击 §1 起因）

- **转述流**：视觉模型把图转成文字 → 失败策略（失败锁存 / 盲答）的后果；
- **评审流**：字段分工表——`评审模型`（谁评）／`触发方式`（何时评）／`轮次`（评几轮）／`自动修订`；
- **触发方式二态对照**（带当前值）：

| 触发方式 | 谁触发 | 命中关键词组时发生什么 |
|---|---|---|
| `手动` | 只有 `/kimi-tide review` | **什么都不发生**（关键词命中不参与） |
| `关键词组` | 命中所选组 ≥1 词即武装 | 本轮**照常执行**，**轮末异步**评审一次；该组的**路由规则被静态抑制**（认领） |

- 轮末评审的边界：每轮只在首个模型步判定一次；带显式 `@` 不武装；本轮无产出不评审；报错/中止轮不评审；评审模型不可用时**只提示不静默**（1.1.0 盲区标注）。

### ⑤ 用量与余额源（依赖：若与「用量/余额全覆盖」同版则按新行为写）

每个源是什么（kimi Code 周/5h 窗、zai 积分制、deepseek 余额、qwen 无 API 面）、多久刷一次、**为什么显示 `—`**（无源／无凭据／取数失败三态区分）、`(过期)` 的含义、余额各分项（总额/赠送/充值）。

### ⑥ 术语小表

打底、命中、特异度、认领、轮末评审、锁存/盲答/懒转述、keep、`stale`、effort 档位。一条一行：术语 → 一句话定义 → 在哪能看到它。

### ⑦ 常见疑问（症状 → 原因）**——本设计的第二核心**

| 症状 | 可能原因（按概率序） |
|---|---|
| 我配了评审模型但没评审 | 触发方式是「手动」；或本轮无产出；或消息带显式 @；或评审模型不可用 |
| 面板没有决策原因条 | 本步是打底或 keep（设计上不上 chip） |
| 额度槽显示 `—` | 当前目标 provider 无配额源；或 key 未配置；或取数失败（看取数时间是否 `(过期)`） |
| 路由没按预期切模型 | 规则链首条命中生效——可能有更靠前的规则先命中（看决策目标 chip 与决策理由） |
| 关键词没命中 | 纯 ASCII 词按词边界、中文按子串；或该组被评审流认领后规则被抑制；或 `minHits` 较高 |

### ⑧ 命令清单（一行一条）

`/kimi-tide show`、`panel --json`、`export-config`、`import-config <path|inline YAML>`、`refresh`、`review`（+ 各自一句话用途）。

## 4. 状态感知（当前值）机制

- **数据来源**：`SettingsCard` 的 `snapshot`（`useSyncExternalStore`，:455 附近）——纯读，不新增通道、不新增宿主面。
- **哪些条目带当前值**（首版范围，宁缺勿滥）：预设激活项、打底目标、规则条数与首条命中条件、评审流**触发方式 + 组 + 评审模型**、转述流失败策略、关键词组数与所选组的词数、各用量源可用性（若无宿主数据则降级为纯静态文案）。
- **渲染形态**：条目末尾一行 `.kt-help-live`，如 `当前：手动 —— 关键词命中不会触发评审`；**值缺失时整行不渲染**（不显示「未知」，避免新的噪音）。
- **不复制配置写入路径**：说明页**只读**，任何交互都不存在（避免第二个写入口）。

## 6. 页签 a11y 修复（C11/N5，随本特性一并还清）

现状：`role="tablist"` + `role="tab"` 有了，但**缺 `tabpanel`、`aria-controls`、方向键**；面板切换靠 CSS `display:none`。

处置：

1. 每个面板加 `role="tabpanel"` + `id` + `aria-labelledby={tabId}` + `tabIndex={0}`；页签按钮加 `id` + `aria-controls`；
2. **非活动面板改用 `hidden` 属性**（保留 CSS 规则作双保险）：`hidden` 与 `display:none` 视觉等价，但语义正确（移出无障碍树与页内查找），且**区块仍保持挂载**——⑥-B「保持挂载」的既有理由不受影响；
3. 键盘：`←/→` 循环切换、`Home/End` 跳首尾、焦点随选中项移动（roving tabindex 或直接 focus）；
4. 说明页内容自身用语义标签（表格 `caption`、术语表 `dl`），并对折叠区补 `summary` 文案（`<details>` 自带可访问名）。

## 10. 未决与风险

| # | 项 | 处置 |
|---|---|---|
| 1 | **文档腐烂**（最大风险）：特性改了说明页没改 | §7 防腐烂闸（特性键存在性断言）+ 「新增特性同提交补条目」发布检查项 |

### 11.1 必改项处置
