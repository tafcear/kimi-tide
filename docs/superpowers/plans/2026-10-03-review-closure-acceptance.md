## A1 · 手动退回最小回路（R2 时序，重点）

| 步骤 | 期望 |
|---|---|
| 1. 干一件活（能让评审挑出毛病的活，如「写一段没测试的解析函数」），等这一轮跑完 | 正常产出 |
| 2. 打 `/kimi-tide review` | 出现**评审卡**，带结论标签（通过/有条件通过/不通过） |
| 3. 点评审卡上的「**让它重做**」 | 卡上回显「已按评审意见退回重做（第 1 次）」；**会话流里出现退回卡** |
| 4. 观察下一轮 | 主模型**收到一条「按意见修订」的注入消息**（会话流里那条 context 行，带 `kimi-tide-revise` 来源），并只改被指出的问题 |
| 5. 等这一轮跑完 | 若复检开：**再出一张评审卡**（评的是重做后的产出） |
| 6. 查会话日志 | 有 `kimi-tide/review-revise` 事件；重启宿主后**该会话仍能打开**（事件类型注册有效） |

**失败即缺陷的观察点**：点了没反应 / 起了新轮但主模型没看见意见 / 退回后评审卡把「人类需求」显示成注入文本（说明 source 判别失效）/ 一次退回触发两次评审。

## A2 · 自动模式

| 步骤 | 期望 |
|---|---|
| 1. `自动修订` 开、`触发方式`=关键词组 `review` | — |
| 2. 发一句含「评审/审查」的话干活 | 轮末自动评审 |
| 3. 评审判「不通过」 | **无需点击**，自动出现退回卡 + 主模型开始重做 |
| 4. 评审判「通过」的一轮 | **不退回**（不打扰） |

## A3 · 终止（达上限）

`轮次=1`、自动修订开：让重做后的复检**再判不通过** → 期望出现「**已停（达上限）**」的退回卡，**不再自动重做**。

## A5 · 复检开关

同一场景把「修订后复检」关掉再做一次 A1：重做那一轮**不再出现第二张评审卡**（少一次评审调用）。

## A6 · 回归（默认关时的行为不变）

`自动修订` 关、`触发方式`=关键词组：仍只出评审卡与意见，**不会**自动改任何东西。
